## Issues & Fixes

- 三角形がライト方向に対して明暗がつくようになるところ、暗いままだった。

　　原因：法線Nとライト方向が逆向き（裏面扱い）になっていた。

　　　　　Lambertの法線とライト方向の内積の計算で、負の値になりsaturate関数のクランプで0になったため拡散反射が消えていた。

　　解決方法：頂点の法線を（0, 0, 1）から（0, 0, -1）に変更し、カメラから見る表面を表側の向きに合わせた。

　　　　　　　今回は三角形が原点の位置にあり、カメラはZ＝-5の位置のため、カメラから見える表面は手前側なので表面の法線は-Zが自然。

　　　　　　　そのため、頂点法線を（0, 0, 1）にしているとカメラから見た面は裏面扱いになり、暗く映っていた。


## Learning

- Lambert（拡散反射）

　　Lambert（拡散反射）拡散反射は、表面が「ザラザラで光をあらゆる方向に均等に散らす（マット）」と仮定したときの反射モデル。

　　現実でいうと、白い紙、チョーク、石、マット塗装みたいな「テカりが少ない」見た目の基本になる。

　　光が表面に当たるとき、面が光に対して斜めになるほど「同じ光量がより広い面積に広がる」ので、単位面積あたりの光の密度が下がって暗く見える。
　　逆に、面が光に正面を向くほど光が集中して明るく見える。

　　この「正面ほど明るい」「90度で境界」「裏側は暗い」という関係を、最もシンプルに数式化したのが Lambert。

　　計算の変数：

　　　　N：モデル空間 → ワールド空間に変換

	L：ワールド空間で定義したライト方向

　　　　N と L が別の空間にいると dot が意味を持たなくなる

　　　　今回は ワールド空間に統一して計算した

　　計算による変化：

　　　　dot(N, L) は「面が光にどれだけ正面を向いているか」を表す

　　　　1：正面（最も明るい）

　　　　0：90度（境界）

　　　　負：裏側（光が当たっていない扱い）→ max(0, …) で 0

　　また、Lambert は N と L が 単位ベクトルである前提で明るさを決める。

　　正規化しないと、ベクトルの長さの影響で明るさが不自然になったり、スケールの影響を受けたりする。

- LightDir の定義（符号反転が起きる理由）

　　方向光は定義が2通りあって混乱しやすい

　　LightDir を「光が進む向き」とする（例：上→下なら (0,-1,0)）：

　　　　この場合、Lambert に必要な L（面→光）は逆向きなので L = -LightDir

　　LightDir を「面→光の向き」とする（例：太陽方向が上なら (0,+1,0)）：

　　　　この場合は L = LightDir のまま

　　今回のような「符号を変えると暗い/明るい」は、LightDir の定義と N の向きが噛み合っていないことが原因になりやすい。

- cbuffer の 16byte アライン

　　float3 は 12byte なので、cbuffer では 16byte 境界に揃えるため padding が必要。

　　C++ 側の構造体も同じ配置にしないと、ライト値が壊れて予期せぬ描画になる。

- 今回の計算式（まとめ）

　　N = normalize(normalWorld)

　　　　表面の単位法線ベクトル

　　L = normalize(面→光方向)

　　　　点から光へ向かう単位ベクトル

　　ndotl = saturate(dot(N, L))

　　　　二つのベクトルの内積（saturate でクランプ）

　　　　cos(θ) に比例して明るさが変わる（θは N と L のなす角）

　　diffuse = LightColor * ndotl

　　　　光の色に明るさをかけたもの

　　final = (Ambient + diffuse) * Albedo

　　　　最終的な光（明かり）の計算に元の色をかける
